# Local runtime verification · 2026-10-10

This is application evidence, not a production release or deployment approval.
Environment: WSL/Linux, Docker 29.1.3, Linux amd64, four available host CPUs.
Production composition, proxy, secret delivery, budgets and Coolify execution
belong to private vps-ops. No remote deployment or image publication occurred.

## Scoped implementation

- API image: dependency stage installs the frozen production lock; runtime omits
  uv/uvx, retains Git for public-corpus synchronization, runs UID/GID 65532 and
  handles SIGTERM. The Debian PCRE security package is explicitly pinned to
  10.46-1~deb13u3, verified available from trixie-security.
- Local PostgreSQL: 512 MiB, 0.75 CPU, 128 PIDs; shared_buffers 128 MiB,
  work_mem 4 MiB, max_connections 50. Neo4j: 1536 MiB, 1 CPU, 192 PIDs,
  heap/page cache 256 MiB each. Both disable extra swap, use rotating logs,
  no-new-privileges and loopback-only development ports. Existing durable volumes
  remain intact. No database major upgrade or production-stack change.
- A shutdown smoke found a persisted run still `running` after process exit.
  Interruption cleanup is now tracked/drained before closing storage; the test
  covers request cancellation while its database write remains pending.
- The existing CI Compose validator now also checks the actual local specification.
  Container smoke rejects runtime build tools and missing corpus Git support.

The pre-security-package multi-stage candidate reduced Docker-reported image size
from 294,193,247 to 272,875,120 bytes (7.2%). This is a same-host image metric, not
registry download size or browser performance. Database observations after fixture
work were approximately PostgreSQL 46–49 MiB and Neo4j 697–883 MiB; these are
samples, not peak guarantees. The fixtures passed within the proposed ceilings.

## Remaining release blockers

1. Citation marker mapping: seven of thirteen live samples contained a numeric
   reference larger than the compact returned source list. Sources belong to the
   retrieved evidence, but original indices are lost when unused entries are
   filtered. Preserve explicit indices or remap text and references together;
   test streaming, final answers and history with noncontiguous citations.
2. Natural Spanish topic switching: “Ahora contame un ejemplo concreto de su
   trabajo en Teamcubation” retained the prior Rampy retrieval anchor. A direct
   Teamcubation question succeeded. Existing fixture examples do not cover this
   variant. Fix context policy and add a regression before claiming continuity.
3. Paid evaluation isolation: the canonical guard checks PostgreSQL but does not
   yet prove Neo4j isolation. This experiment separately verified both owned
   loopback containers and a fresh database. Add both checks to the maintained
   harness; do not treat the session-specific guard as its implementation.
4. Backoffice: the proposed private `/internal/ops/v1/status` contract is not
   implemented by this API. Fixture dashboards are not real metric integration.
5. Image security: full scanner output remains a gate requiring review. Some
   HIGH findings report msgpack/setuptools/old urllib3 from base-layer metadata
   without installed paths; runtime Python contains only urllib3 2.8.0 for these
   names. Do not suppress them without verifying provenance. OS HIGH findings
   also remain; rebuilding successfully is not a clean security assessment.
6. Neo4j patch freshness: official 5.26 changelog identifies newer security patches,
   but the attempted 5.26.32-community registry inspection returned “not found”.
   Keep the verified 5.26.17 digest rather than inventing an artifact. Confirm an
   available supported patch, scan it and test restored fixture data before updating.
