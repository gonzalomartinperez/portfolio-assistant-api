## Lens summaries

### Developer

- Layering is genuinely enforced: an AST import guard with bypass-probe negative fixtures and a zero-violation assertion runs in the required job.
- Static hygiene is good on the configured scope, but the rubric's strict bar is not: 89 `mypy --strict app` errors, no complexity or dead-code gate, and 11 functions over CC 10.
- The test portfolio is broad (unit, real-DB integration, contract with Schemathesis/oasdiff, property, container smoke) with diff coverage gated at 90%; mutation and flake evidence is missing.
- CI is a single fail-closed `ci-gate` with path profiles and a p50 of about 6 minutes; release is tag-only, so no digest promotion is shown.
- Supply chain is pinned and scanned, but there are no SBOM/provenance artifacts, and every scheduled workflow (load, mutation, vuln, cross-repo, OpenSSF) is dormant because schedules run only from `main`.

### Designer (DX, docs, contract ergonomics)

- The SSE contract is the strongest design asset: a typed envelope, ordered progress events, exactly one terminal, keep-alive and reconnect via run state.
- The error contract is consistent and safe but minimal: not RFC 9457, English-only, codes undocumented in the schema.
- Contract artifacts are complete and drift-checked, but the OpenAPI itself is bare (no descriptions or examples), so the reference only works alongside the prose doc.
- Local onboarding is careful about isolation (own ports and project names) but is a multi-step manual sequence, not one command.
- The docs structure follows Diataxis, with a clear README documentation table.

### Recruiter

- The first screen states what the product is and why it matters in one sentence, with a real UI screenshot and C4 diagrams.
- Writing is precise and credible; the limits are stated honestly, which reads as senior.
- The proof section undercuts itself: half the measured rows are either unflattering or "not measured", and there is no answer-quality number.
- There is no link to try the assistant or watch a recorded demo, and the release badge renders empty.
- Differentiation (validated citations, spend cap, bilingual evals, GraphRAG) is clear for a technical reader.

## Highest-leverage gaps

1. P3: golden pass rate is unmeasured. Commit the owner-approved cassettes and a CI or report artifact showing 80/80 replay with per-locale and per-stratum results (abstention, language).
2. D2: strict typing and complexity. Bring `mypy --strict app` from 89 to 0 errors and add C901 (max 10) plus a dead-code check (vulture or equivalent) to the gate, starting with `ai/retrieval.search` (49) and `indexing._sync` (31).
3. D6/P2: load budgets never ran. Run `load-nightly.yml` (via workflow_dispatch, or a push trigger until `main` carries it) and commit the report showing TTFE p95 against 1500 ms.
4. D5: no SBOM or provenance. Generate an SBOM (Syft or BuildKit `sbom=true`) and a provenance attestation for the api/worker images in CI and keep them as artifacts.
5. D3: mutation and flake evidence. Run the full weekly mutmut campaign, set per-group ratchets above `break`, end warn mode, and publish a 30-day flake report for the required checks.
6. D4: no build-once promotion. Publish the tested image digest once and have release/deploy reference that same digest (recorded in the release notes).
7. P1: error contract. Adopt RFC 9457 problem+json (keeping `code`/`request_id` as extensions), add locale-aware messages, and enumerate error codes in OpenAPI.
8. D7: SLOs and propagation. Write availability/latency SLOs with error budgets, and honour an inbound `X-Request-ID`/`traceparent`.
9. P5: consumer verification. Execute `cross-repo.yml` (dispatch) and add a consumer contract check proving the portfolio snapshot matches contract hash v1.
10. Recruiter/D8: README proof and setup. Cut a GitHub Release so the badge renders, add a one-command `just up` fixture demo and a short recorded walkthrough, and surface one answer-quality metric.
